Acuan Migrasi ERP

Satu index.html, vanilla JS, tanpa bundler. Angka di halaman ini dihitung oleh aturan bisnis asli yang dipancarkan ke portabel/ — bukan disalin ulang.

1. Aturan bisnis dipakai apa adanya

Semua angka di atas keluar dari modul yang sama dengan yang dipakai aplikasi Next.js. Tidak ada rumus yang ditulis ulang di halaman ini. Contoh kecil yang menular: sebuah baris RAP tergolong Subkon karena kolom kategori-nya, bukan karena namanya memuat kata "subkon". Menebaknya dari nama menghasilkan angka yang salah tanpa galat.

2. Jebakan angka gaya Indonesia

"1.250" dan "12.5" sama-sama satu titik tetapi berbeda arti. Inilah alasan pembacaan isian tidak boleh ditulis ulang — pakai angkaIndonesia() dari portabel/adaptor/formulir.js.

3. Invarian tetap ditegakkan

Jumlah pembebanan wajib sama dengan total pembayaran. Kalau invarian ini hilang saat aksi menjadi RPC, biaya per unit diam-diam tidak lagi sama dengan total pengeluaran — dan tak ada galat yang muncul.

4. Pola pemanggilan Supabase RPC

import { buatKlienRpc, ditolakIzin } from "./rpc.js";

const { rpc } = buatKlienRpc({
  url: "https://<proyek>.supabase.co",
  anonKey: "<anon key>",
  token: () => sesi?.access_token ?? null,
});

// Nama fungsi diambil dari KONTRAK-RPC.md — 77 aksi tulis
// beserta izin yang harus menjaganya.
try {
  await rpc("pm_simpan_fase", { p_proyek: "NT2", p_kode: "F1" });
} catch (e) {
  if (ditolakIzin(e)) tampilkan("Anda tidak berhak melakukan ini.");
  else throw e;
}
Penjagaan izin ada di dalam fungsi Postgres (SECURITY DEFINER, periksa izin di baris pertama) — bukan di JavaScript ini. Siapa pun bisa membuka devtools dan memanggil rpc() sendiri.
